# 개발 방식과 수정 기록

이 문서는 현재 소스와 제작 중 플레이 피드백을 바탕으로 정리한 회고입니다. 정확한 개별 수정 날짜, 작업 시간, 성능 개선율은 측정하지 않았으므로 기재하지 않았습니다.

## 1. 작은 구간으로 조작을 먼저 검증

처음에는 사방치기만 구현해 한 번 탭과 두 번 탭의 리듬을 검증했습니다. 이후 턱 걷기와 횡단보도를 추가하고 `ISectionGameMode`로 구간의 준비·시작·종료를 묶었습니다. 한 개의 거대한 GameManager에 모드별 규칙을 넣지 않고, 각 컨트롤러가 입력의 의미와 성공·실패 조건을 처리하도록 구성했습니다.

캐릭터와 배경은 기본 도형과 코드 기반 생성으로 만들었습니다. 학생 캐릭터, 주택가, 학교와 모래 운동장·울타리, 차도 배경을 추가했습니다. 고급 그래픽보다 실제 입력이 재미있고 이해 가능한지 확인하는 데 우선순위를 두었습니다.

## 2. 횡단보도: 연타와 거리 판정

**발견한 문제:** 연타 입력이 예약되거나 점프 중 다시 점프되어, 누르지 않았는데도 점프가 발생하거나 공중에서 내려오지 않는 느낌이 생겼습니다. 흰색 간격이 좁으면 연타만으로 통과할 수 있었습니다.

**수정:** `Walking`에서 입력을 받으면 즉시 `Jumping`으로 전환합니다. 점프 중 입력은 저장하지 않습니다. 점프 거리는 2.56, 흰색 길이는 2.4, 간격은 1.6으로 조정해 흰색 끝에서 뛰면 다음 흰색의 40% 정도에 착지합니다. 착지 보정은 최대 0.12로 제한합니다.

**추가 수정:** 첫 구간이 횡단보도여도 인도에서 접근합니다. 신호 대기 위치부터 점프할 수 있으며, 빨간불이면 차가 급정거하는 `NearMiss` 상태를 거쳐 실패합니다. 초록불 또는 무신호 진입에서는 첫 흰색에 실제로 착지했는지 검사합니다. 차량 중심과 전체 바퀴가 차도 안에 있도록 경계 여유를 적용했습니다.

**검증:** 인도 진입 점프, 점프 중 연타 무시, 중복 실패·점수 방지, 차량 경계 검사.

## 3. 사방치기: 반응 장애물과 리듬 판정 분리

**발견한 문제:** 공이 갑자기 나타나거나, 공을 피하려는 입력까지 일반 박자 판정을 받아 빠르게 눌러도 실패했습니다. 공 칸에 착지하면 공이 바로 사라져 회피 동작과 표현이 연결되지 않았습니다.

**수정:** 공을 두 패턴 전에 예고합니다. 공 차례에는 0.85초 안에 한 번 탭하면 즉시 점프하고, 착지 후 0.65초 안에 다시 탭해 다음 칸으로 탈출합니다. 공의 위치는 원래 칸에 유지하며 왼쪽 화면 밖까지 굴립니다. 돌출된 무늬는 제거하고 구체 표면의 검은 오각형 무늬로 축구공을 표현했습니다.

**고속 조정:** 일반 칸의 입력 허용 시간 0.30초와 늦은 입력 유예 0.15초를 속도 배율로 축소하지 않습니다. 다음 입력 박자까지 최소 0.30초를 확보하고, 음악·점프 속도와 입력 여유를 분리했습니다. 한 칸에서 두 번 누르는 등 잘못된 횟수는 여전히 실패합니다.

**검증:** 공 칸 진입과 탈출, 머무르면 실패, 공 시각화 유지·퇴장, 일반 리듬 허용 오차.

## 4. 턱 걷기: 바람이 오히려 쉬워지는 문제

**발견한 문제:** 반대 방향으로 한 번 탭한 뒤 복귀가 너무 느려져, 오히려 추가 입력 없이 버틸 수 있었습니다. 낙엽만으로는 바람이 불고 있음을 알아보기 어려웠습니다.

**수정:** 탭 시 기울기 진행 방향을 즉시 반전하고, 바람은 이후 시간에 따라 기울기 속도에 영향을 줍니다. 바람이 다시 방향을 돌릴 수 있도록 했으며 속도 상한을 둡니다. 낙엽·나무 흔들림·작은 바람 소리를 함께 제공하고, 거슬리는 소리는 부드럽게 조정했습니다. 고속에서는 추가 기울기 배율을 적용합니다.

**검증:** 방향 반전, 바람 종료 후 기본 동작 복원, 재시작 초기화, 효과 숨김과 음원 정지.

## 5. 세트별 장애물과 음악 동기화

한 세트에 세 모드가 한 번씩 나오도록 shuffle bag을 사용하고 세트 경계의 연속 중복도 피합니다. 첫 세트에는 장애물이 없고, 이후 대상 구간을 1개·2개·3개로 늘립니다. 5세트부터 0.1배씩 증가하여 8세트부터 1.4배 상한을 유지합니다. 단, 횡단보도 신호는 1.2배 이상일 때만 나타납니다.

다음 구간을 미리 만들 때는 그 구간에 해당하는 설정으로 길이를 계산한 후 현재 구간 설정을 복구합니다. 실행 중 구간의 속도가 선생성 때문에 바뀌지 않게 합니다.

음악은 재생 위치를 유지하며 pitch를 바꾸고 DSP 박자 기준을 다시 계산합니다. 이 방식은 템포와 음높이가 함께 변합니다. 입력 유예와 준비 시간은 플레이 가능성을 위해 별도로 유지합니다. 최대 난이도로 바로 시작하는 테스트 설정을 사용해 검증한 뒤 정상 진행으로 되돌렸습니다.

## 6. 증거와 남은 한계

- 최신 정상 진행 복구 버전의 PlayMode 52개가 통과했습니다. 이름과 결과는 `verification.json`에서 확인할 수 있습니다.
- PC 빌드 화면을 캡처하여 UI 가독성, 축구공 외형, 차량의 차도 위치를 확인했습니다.
- 초기 Android 설치·실행 확인은 있었으나, 최신 변경 전체에 대한 실기기 검증은 남아 있습니다.
- 다수 사용자 테스트, FPS·메모리·발열 지표, 정량적인 재미 개선율은 아직 없습니다.
- 기획과 플레이 피드백은 제작자가 진행했고, 코드 구현·자동 검증·문서화에는 AI 지원을 사용했습니다.
